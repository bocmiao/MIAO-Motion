# MIAO Motion 验收清单

本文件是验证与发布证据清单，不是开发阶段的前置 Gate。任何可独立完成的代码都可以继续推进；未完成项必须如实保留，并在发布说明中标为已知问题。P0 只影响是否把某个构建标记为正式稳定版，不阻止后续功能开发。

## v0.3.0 新增设备验收

- [ ] 原创猫咪 → 摄像头或语音 → OBS/直播姬全流程。
- [ ] 原生摄像头安装、接收、停止、重新启动、卸载；记录接收软件位数与版本。
- [ ] 身体/手指入镜、遮挡、镜像、缺骨骼角色、长时间运行。
- [ ] iFacialMocap 指定手机、断网、停止、防火墙及端口占用。
- [ ] 自动画质在低配机降级并恢复，首帧等待无提前“可用”。
- [ ] 至少三名新手独立体验并记录卡点。
- [ ] 已有账号资源后按 [分发接入说明](DISTRIBUTION_SETUP.md) 验证镜像与签名。

## 1. 延续自 v0.2.1 的真实硬件验收

### P0 功能

- [ ] Windows 11 当前稳定版实机可启动本地版本。
- [ ] 免 Node.js 便携 ZIP 解压后可由 `start-portable.bat` 启动，离线资源完整。
- [ ] 第一次普通页面启动会打开四步引导，完成后不再自动弹出。
- [ ] 右上角“新手教程”可以重新打开引导。
- [ ] 没有 VRM 的用户能从应用内找到 VRoid Studio 制作与导出路径。
- [ ] 至少一个笔记本内置摄像头和一个 USB 摄像头可开启、切换和释放。
- [ ] VRM 0.x、VRM 1.0 各至少两个模型可加载。
- [ ] 头部向左、向右、抬头、低头和侧倾方向正确。
- [ ] 左右眼眨眼没有互换。
- [ ] 张嘴、圆嘴和微笑可见；缺少表情的模型不会报错崩溃。
- [ ] 正面校准后静止姿势不会持续漂移。
- [ ] 人脸离开画面后角色平滑回正，返回后能自动恢复。
- [ ] VRoid 骨骼型与表情型 LookAt 的眼神方向都正确。
- [ ] 镜像开关统一改变头部左右、单眼眨眼和左右视线；默认值符合多数用户直觉。
- [ ] 导入模型后双臂处于自然下垂姿势，无人脸时会呼吸并自动眨眼。
- [ ] 绿幕和透明背景切换正确。
- [ ] 最后导入的模型刷新页面后可以恢复。
- [ ] 关闭摄像头后 Windows 隐私指示在 1 秒内熄灭。
- [ ] 连续快速点击两个摄像头入口只产生一个流，关闭后所有 track 为 `ended`。

### P0 错误处理

- [ ] 非 VRM 文件给出中文错误且程序继续运行。
- [ ] 损坏 VRM 不导致白屏。
- [ ] 超过 200 MB 的模型在解析前被拒绝。
- [ ] 拒绝摄像头权限后可以再次点击重试。
- [ ] GPU 初始化失败能尝试 CPU。
- [ ] MediaPipe 下载失败给出可重试提示。

### P1 质量

- [ ] Windows 10 22H2 实机可启动；失败时作为尽力兼容项记录，不阻断 Windows 11 首发。
- [ ] 720p 摄像头、脸部模式平均追踪 ≥15 FPS。
- [ ] 连续运行 60 分钟无崩溃。
- [ ] 导入第二个模型后，第一个模型的资源被释放。
- [ ] 模型医生的 4 项动作能力与模型实际能力一致。
- [ ] 三角面、材质、贴图尺寸和内存估算与测试模型基本一致。
- [ ] 性能风险分级在低/中/高配测试机上不会明显误导用户。
- [ ] 设置导出后可重新导入，文件不含摄像头编号或模型内容。
- [ ] 删除本地模型二次确认后清除浏览器副本，不影响原始文件。
- [ ] 诊断报告不含摄像头画面、模型内容、用户目录全路径或设备编号。
- [ ] OBS 30.x/31.x 浏览器源能否导入/恢复模型、取得摄像头已形成明确结论。
- [ ] 绿幕窗口捕获时，窗口最小化或完全遮挡是否冻结已记录；教程与结论一致。
- [ ] 哔哩哔哩直播姬、抖音/快手直播伴侣、腾讯会议接入教程的菜单名和截图已在真机复核。

## 2. v0.3.0 桌面版验收

### P0 安装与离线

## 4. v0.5.0 身体与进阶输出验收

- [ ] 正面站立校准可以完成。
- [ ] 肩、胸、脊柱、上臂和前臂方向正确，左右肢体不互换。
- [ ] 手臂短暂被遮挡时保持最后可信姿势，然后平滑回落。
- [ ] 任何单帧异常不会让骨骼超过设定角度。
- [ ] 可以单独关闭身体/手部追踪并继续使用脸部。
- [ ] 双手出现/消失不会导致角色闪烁；低性能档默认关闭手部。
- [ ] 推理不阻塞渲染超过 100 ms，推荐机渲染 P95 帧时间 ≤20 ms。
- [ ] Spout2 spike 有明确结论：采用、实验或放弃，并记录性能数据。
- [ ] 如果采用 Spout2，1080p60 连续 60 分钟无黑帧和纹理泄漏。
- [ ] OBS WebSocket 连接使用 5.x，认证默认开启。
- [ ] OBS 密码不出现在日志、URL、崩溃报告或截图中。
- [ ] 自动创建来源前显示将执行的操作，并允许取消。
- [ ] 自动配置失败时，新手文档能在 5 分钟内完成手动设置。

## 5. v1.0 发布验收

### 功能冻结

- [ ] `PROJECT_PLAN.md` 中全部 P0 功能完成或有经过记录的范围调整。
- [ ] 没有 P0/P1 已知崩溃、数据丢失或隐私缺陷。
- [ ] 10 名第一次使用者中至少 8 人在 10 分钟内完成首次动捕。
- [ ] 10 名第一次使用者中至少 8 人在 20 分钟内完成 OBS 接入。

### 兼容性

- [ ] Windows 10/11、NVIDIA/AMD/Intel 测试矩阵完成。
- [ ] 至少 10 个具有合法测试权的 VRM 覆盖 0.x/1.0 和表情差异。
- [ ] 中文路径、非管理员账户和多显示器环境通过。

### 稳定与恢复

- [ ] 推荐机连续运行 2 小时无崩溃。
- [ ] 摄像头拔出再插入可以恢复或给出明确重试按钮。
- [ ] 应用异常终止后配置和模型库不损坏。
- [ ] 自动更新失败仍能启动上一版本。

### 发布物

- [ ] Windows 安装包。
- [ ] Windows 便携压缩包。
- [ ] SHA-256 校验文件。
- [ ] MPL-2.0、第三方许可、隐私说明和安全报告入口。
- [ ] 新手教程、OBS 教程、模型问题教程和已知问题。
- [ ] GitHub Release 与 tag 指向相同提交，CI 全绿。

## 6. 缺陷优先级

| 等级 | 定义 | 示例 | 发布处理 |
|---|---|---|---|
| P0 | 数据、隐私、安全或核心链路完全不可用 | 摄像头帧上传、模型损坏、应用无法启动 | 必须阻断发布 |
| P1 | 核心能力明显错误且无合理绕过 | 头部轴反向、OBS 黑屏、常见 VRM 崩溃 | 正式版必须修复 |
| P2 | 有绕过方式的功能或体验问题 | 某摄像头需重试、提示文案不清 | 可记录后发布 |
| P3 | 优化或低频问题 | 边距、动画细节、罕见模型提示 | 进入后续版本 |
