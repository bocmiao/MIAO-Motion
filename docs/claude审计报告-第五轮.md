## 一、结论

Codex 按第四轮报告逐项整改，**大部分确实修好了**，并新增了捏人 v2、首页三入口、平台向导，身体识别也移进了后台线程。我实际操作过：新功能能用，导出的角色可以重新导入。

但有四个问题需要优先处理：

1. **修复还没发布**。用户现在能下载到的仍是 `v0.3.0-beta`，其中包含提权隐患、卸载残留，以及手机面捕、手指、VRM 0.x、镜像四项功能失效；下载页仍在引导用户下载它。

3. **镜像约定仍不一致**。镜像开启时，身体和头部是"照镜子"的方向，眼睛和视线却不是。
4. **平台指南一行没改**，仍然自相矛盾。

## 四、本轮问题清单

### 4.1 P1

**① 修复没有发布，公开版本仍有已知问题【实测：GitHub API】**

- 公开的只有 `v0.3.0-beta`。它仍然会：
  - 以管理员身份注册用户可写目录里的 DLL（提权隐患）；
  - 卸载时不注销组件（留下幽灵摄像头）；
  - 手机面捕只剩张嘴、手指不动、VRM 0.x 四肢方向错、身体镜像反。
- 它的安装包 `.sha256` 文件名仍然写错。
- `download.html` 仍然引导用户下载"最新 Pre-release"来使用虚拟摄像头；发布说明里没有任何安全提醒。
- `docs/BETA_RELEASE_NOTES.md` 目前写着"第四轮整改候选说明（尚未发布）"，属于面向发布者的内部文字，发布时会原样成为 Release 正文。
- **整改**：
  1. **立即**：给 v0.3.0-beta 的发布说明加醒目警告：不要使用虚拟摄像头；已经安装过组件的用户，请先在旧版里点"卸载摄像头组件"。同时重新上传正确的 `.sha256`（哈希值不变，只改文件名）。
  2. 改写发布说明，写给用户看，包括旧版升级和清理步骤。
  3. 发布 `v0.3.1`，发布前在 release 流程里跑完整的浏览器测试和四色方向测试（目前 release 流程不跑这两项）。

**② 卸载死锁：几种常见情况下，喵动卸不掉【源码，本人复核】**

- **位置**：`src-tauri/windows/hooks.nsh:5-10`
- **原因**：钩子只要检测到电脑上有这个组件的注册就强制注销，注销失败就中止卸载。以下情况都会卸不掉：
  - 用户在 UAC 弹窗里点了"否"；
  - 没有管理员密码的电脑（学校、公司、家长管控）；
  - 组件是同一台电脑上**另一个用户**注册的，当前用户自己从没装过组件，也卸不掉自己的喵动。
- **整改**：
  - 新版组件已经在受保护目录里，保留注册并不危险。注销失败时应弹出"是否仍然卸载喵动？（摄像头组件会保留，可稍后清理）"，让用户继续卸载；
  - 注册时在当前用户注册表记一个标记，卸载时只注销本人注册的那份；
  - 把注册工具也复制进 `Program Files\MIAO Motion Camera`，并提供开始菜单里的"清理喵动摄像头组件"入口，方便管理员以后清理。

**③ 旧版迁移有缺口【源码】**

- **位置**：`hooks.nsh:17-21`
- **问题一**：从 v0.3.0-beta 升级时，如果用户拒绝 UAC，迁移失败，旧注册仍然指向用户目录里的 DLL，提权隐患依然存在。这时的提示却写"其他功能可正常使用"，完全没提安全风险。
- **问题二**：直接卸载 v0.3.0-beta 的用户（旧卸载器没有钩子），系统里会残留指向已删除文件的注册，目前没有任何清理工具或说明。
- **整改**：迁移失败的提示要写明风险，并告诉用户怎么清理；提供独立的"旧版摄像头组件清理工具"，或者写一份清理说明。

**④ 镜像约定仍不一致【实测 + 源码，最终方向需真机】**

- **位置**：`src/avatar-utils.mjs:54` 的 `mirrorMotion`：只在**关闭**镜像时交换眼睛和视线的左右，开启时不交换。身体求解器在开启镜像时会交换左右，头部左右转动在开启时是"照镜子"的方向。
- **实测**：子任务在官方人像图上涂闭本人左眼，MediaPipe 的 `eyeBlinkLeft` 升高。即 MediaPipe 的 "Left" 是本人左眼，与 iFacialMocap 的 `_L` 一致。
- **后果**：默认开启镜像时，同一个人同时闭左眼、举左手，角色会在画面两侧分别动作。
- **需要注意**：无论 MediaPipe 的约定最终是哪种，眼睛、身体、头部、手机这四条路径里**总有一条和其他不一致**。这是结构问题，不只是符号问题。
- **测试漏洞**：
  - 测试 `tests/avatar-utils.test.mjs:24` 的名字就是"镜像只在关闭时交换"，把不一致写成了预期；
  - 手机测试夹具的左右数值是对称的（7/7、0/0），查不出左右调换。
- **整改**：写一个统一的"镜像约定"模块，四条路径共用；测试数据必须是非对称的（只闭一只眼、只举一只手、只向一侧转头），断言四条路径方向一致；最终默认方向用真机确认。

**⑤ 平台指南一行没改，仍然自相矛盾【本人复核】**

- `docs/LIVE_PLATFORM_GUIDE.md`：
  - 第 46 行写"当前没有原生虚拟摄像头"，第 68 行又写"安装版现可输出"；
  - 第 5 行声称平台页包含虎牙、斗鱼、视频号，实际没有；
  - 第 3 行仍写"尚无真实 Windows 设备"；
  - 没有小红书。
- 新手教程 `BEGINNER_GUIDE.md:133` 还把用户引到这一页。
- **整改**：按平台向导的内容重写这一页，或者直接删掉，统一指向 `platforms.html`。

**⑥ 手机面捕说明仍然不够【源码】**

- `new-features.html:11`、`index.html:215` 仍然没写：
  - iFacialMocap 是付费 iOS App；
  - 需要带 Face ID 的 iPhone 或 iPad；
  - 安卓用户怎么办（直接用电脑摄像头即可）；
  - 网络被识别为"公用网络"时会被 Windows 防火墙拦截，以及怎么改成"专用网络"；
  - 当初在防火墙弹窗里点了"取消"，之后怎么放行。
- 程序只发一次握手包，一直收不到数据时也没有排查提示。

## 七、需要你安排

1. **发布决策**：是否立刻给 v0.3.0-beta 加警告，或者直接下架它的安装包（只保留便携版）。
2. **真机测试**（重点）：
   - 卸载：在 UAC 弹窗点"否"；用标准用户账户；两个 Windows 用户分别安装；从 v0.3.0-beta 升级。
   - 镜像方向：同时闭左眼、举左手、向左转头，看角色三处是否在同一侧。
   - 手机面捕：转头方向是否与摄像头一致。
   - 虚拟摄像头在腾讯会议、钉钉、直播伴侣中的表现。
3. 美术（正式版喵小动和更多部件）、代码签名、国内镜像。
