## 一、结论

Codex 这一轮做了大量扎实的工作：第一轮报告里的 P1 缺陷大部分确实修对了；还新增了模型库、配置档、便携包、Tauri 外壳、离线帮助、CSP、E2E 测试等，数量和质量都超出预期（核实结果见第三节）。

但是 **“能做的都做完了”这个判断不成立**。本轮把程序实际跑起来、用真实 VRM 模型操作后，发现：

1. **直播画面是空白的（P0）**。无论点“进入直播画面”，还是用 OBS 地址 `?broadcast=1`，角色都不显示，整屏只有米色背景。这是整个产品的输出环节，而且从 v0.2 起就存在（第一轮我只读代码，没有发现，这里更正）。E2E 测试之所以通过，是因为断言方式有漏洞。
2. **几处动作方向是反的（P1）**：眼神上下颠倒（所有模型）；VRM 0.x 模型的手臂会**抬起**而不是放下，点头和歪头方向也与 VRM 1.0 相反。VRoid Hub 上的大量模型是 0.x。
3. **默认取景切掉了角色的头**（半身预设只拍到躯干；头像预设只拍到下巴），三个取景预设都偏低。
4. **“透明背景”其实不透明**（页面根元素保留米色背景）。

以上问题**全部不需要真机就能修复并自动验证**。另外，按三大方向看，最大的缺口仍然是：

- **拿不到程序**：仓库没有任何 Release，README 让小白去 GitHub Actions 下载（需要登录、英文界面、14 天过期、ZIP 套 ZIP、国内慢）；
- **没有角色**：没有内置示例角色，新手引导第 2 步没有模型就无法继续；制作角色的指导只有 6 行文字；
- **平台对接只停留在“窗口捕获”**：会议软件、视频号、虎牙/斗鱼等没有覆盖，原生虚拟摄像头还没开始。

**建议：交给 Codex 继续做第七节的清单，其中 1–9 项是本周就能完成、不依赖真机的阻断或方向错误修复。**

## 四、本轮新发现的问题

### 4.1 P0：阻断核心使用

**① 直播画面空白：角色和绿幕都不显示【实测】**

- **位置**：`src/style.css:199-205`（`.stage-card { grid-template-rows: auto 1fr }`）、`285-290`（广播模式规则）、`.app-shell` 只设置了 `min-height`
- **现象**：广播模式隐藏了 `.stage-toolbar`，于是 `#stage` 落到 `auto` 那一行，高度变成 0；同时 `.workspace` 是 `flex: 1` 的子项，其父元素只有 `min-height`，`height: 100%` 无法生效。实测在 1280×720 下舞台尺寸为 1280×0，截图整屏米色。带模型、`background=green` 的 OBS 地址同样空白。“还没有可用角色”提示框位于 y=-103，也被裁掉了。
- **影响**：推荐路径“绿幕 + 窗口捕获”和 OBS 浏览器来源都拿不到画面。**这是产品的输出环节**。
- **修复**：广播模式下设置 `.stage-card { grid-template-rows: 1fr }` 和 `.workspace { flex: none }`，或者直接 `.broadcast-mode .stage { position: fixed; inset: 0 }`。审查时临时注入这段 CSS 后，舞台恢复为 1280×800，角色正常渲染。
- **测试**：E2E 必须断言舞台的 `boundingBox` 与视口一致，并对画布截图、检查像素不是纯背景色。`toBeVisible()` 不会因为 `overflow:hidden` 裁剪而失败，不能用它判断“看得见”。

**② 小白拿不到程序【实测：仓库 Release 列表为空】**

- README 和 `BEGINNER_GUIDE.md` 让用户从 GitHub Actions 下载构建产物，这条路有 5 个问题：需要登录、英文界面、14 天后过期、ZIP 套 ZIP、国内访问慢。
- `release.yml` 只会创建草稿 Release，也没有国内镜像。
- **修复**（不需要真机）：发布一个 `v0.2.1-beta` 预发布版（明确标注“测试版、未经真机验收”）；`release.yml` 增加同步到国内镜像（Gitee Release / 对象存储 / 网盘）的步骤；做一个中文下载页，列出 SHA-256。镜像账号需要仓库所有者提供。

**③ 没有角色的小白走不下去【源码】**

- 没有内置示例角色；新手引导第 2 步规定必须导入模型才能点“下一步”（`app-utils.mjs:74`）。没有 VRM 的用户看不到任何动捕效果，只能离开程序去学 VRoid。
- **修复**：见第五节 B。在有授权角色之前，至少允许用户“先跳过、看看摄像头效果”，并把第 2 步改成三选一：用示例角色 / 导入我的 VRM / 教我做一个。

### 4.2 P1：动作方向和画面错误（都能在无真机环境下修复和测试）

**④ “透明背景”其实是米色【实测】**

`:root { background: #f3f0e9 }`（`style.css:1-3`）在广播模式下没有被覆盖，实测计算结果为 rgb(243,240,233)。OBS 浏览器来源和 Tauri 透明窗口都会显示米色底。修复：`html:has(body.broadcast-mode) { background: transparent }`，或者在 `<html>` 上切换一个 class。

**⑤ 输出比例在直播画面中错位【实测】**

`style.css:219-221` 的比例规则与 `290` 的广播规则优先级相同，结果宽度 100% 生效，再由 `aspect-ratio` 推出高度。实测 9:16 时舞台为 1280×2276、位于 y=-1476，1:1 时为 1280×1280、位于 y=-480，角色都被推到屏幕外。修复：广播模式下改为高度 100%、宽度自动、`max-width: 100%` 并居中。审查时验证过：9:16 得到 450×800，1:1 得到 800×800。

**⑥ 三个取景预设都偏低，切掉了头【实测，pixiv 官方 VRM 1.0 示例】**

默认“半身”只拍到躯干（看不到脸）；“头像”只拍到下巴和脖子；“全身”只拍到腰到大腿。`frameModel`（`main.ts:348`）按整个模型的包围盒估算位置，不可靠：头发、裙摆、弹簧骨骼碰撞体都会影响包围盒。**修复**：以 Head 骨骼的世界坐标为锚点（头像：头部居中；半身：头部位于画面上三分之一；全身：再用包围盒保底）。E2E 用示例模型截图，检测头部骨骼投影后是否落在画面内。

**⑦ VRM 0.x 模型的手臂会抬起【实测，合成模型】**

three-vrm 对 VRM 0.x 的规范化骨骼保留了模型原本朝 -Z 的坐标系，X、Z 轴旋转与 VRM 1.0 相反。实测“手 - 肩”的高度差：VRM 1.0 为 −0.484（放下），VRM 0.x 为 **+0.484（举起）**。修复：`vrm.meta.metaVersion === '0'` 时取反 z 角度（three-vrm 官方 mixamo 示例的做法相同）；摆完姿势后调用 `vrm.springBoneManager?.setInitState()`，否则头发和衣袖会在加载瞬间甩动。

**⑧ VRM 0.x 模型的点头和歪头方向与 VRM 1.0 相反【实测，合成模型】**

对规范化头骨施加同样的旋转：VRM 1.0 上 +x 是低头、+z 是向角色右侧歪；VRM 0.x 上 +x 是抬头、+z 是向左歪；左右转头两者一致。因此无论映射怎么定，总有一类模型方向是反的。修复：VRM 0.x 在应用前把相对四元数的 x、z 分量取反。

**⑨ 眼神上下颠倒，所有模型都受影响【源码 + 实测】**

three-vrm 中 `pitch > 0` 表示向下看（表情型 applier 把 pitch>0 映射为 `lookDown`，骨骼型实测 pitch +20 时眼球朝下）。`avatar-utils.mjs:68` 却是 `pitch = (lookUp - lookDown) * 20`，用户往上看时角色往下看。`tests/avatar-utils.test.mjs:31` 断言 `lookUp=1 → pitch: 20`，**测试把这个错误固化了**。修复：改为 `(lookDown - lookUp) * 20`，并同步修改测试。

**⑩ Tauri 桌面版启动时会出现黑色命令行窗口【源码】**

`src-tauri/src/main.rs` 缺少 Tauri 模板自带的 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`。每次启动都会先弹出一个控制台窗口，用户一关掉它，程序也跟着退出。一行代码即可修复。

**⑪ 镜像约定仍不是真正的镜像【源码，最终方向需真机】**

`relativeHeadRotation`：开启镜像时为 (−pitch, −yaw, +roll)，关闭时为 (−pitch, +yaw, −roll)。真正的镜像应当“翻转 yaw 和 roll、保持 pitch 不变”。按 MediaPipe 文档的坐标系推算，两种模式下 pitch 都被取反，而镜像模式只翻了 yaw 没翻 roll。建议先按坐标系推导写成纯函数、配上单元测试；真机上再用“低头 / 向左肩歪头 / 眨左眼”三个动作各在开关两种状态下确认。

**⑫ Tauri 中摄像头权限没有处理，错误提示也不适用【源码 + 需真机】**

`lib.rs` 没有处理 WebView2 的 PermissionRequested。用户一旦在弹窗里点了“阻止”，这个选择会被记住，程序里没有任何恢复入口。错误文案“请在浏览器地址栏允许后重试”（`capture.mjs:15`）在桌面版里没有地址栏可点；Windows“设置 → 隐私 → 允许桌面应用访问相机”也没有提到。修复：对自身 origin 自动授予摄像头权限，并按运行环境（浏览器 / 桌面版）给出不同文案。

**⑬ 便携服务器不够健壮【实测 + 需真机】**

- 请求处理中任何异常（例如浏览器在 11 MB 的 wasm 下载途中刷新）都会逃逸到最外层，服务器直接退出，并提示“无法启动”（`portable-server.ps1:47-57`）。
- 重复双击启动器，或者 4173 端口被占用时，会显示英文红字，也不打开浏览器。4173 恰好是 Vite 预览的默认端口，容易撞上。
- 所有提示都是英文。
- **需真机**：用 `http://127.0.0.1:4173/` 注册 HttpListener，在非管理员账户下可能被 http.sys 以“拒绝访问”拦截。CI 的 Windows 机器以管理员运行，测不出来。
- **修复**：改用 `TcpListener(Loopback, 4173)` 加一个最小的 HTTP 响应器，不需要 URL ACL，也只绑定本机；启动前先探测 `/.build-version`，如果已经在运行就直接打开浏览器；每个请求单独 try/catch；提示改为中文。

**⑭ 引导和直播按钮把小白带进死胡同【源码 + 实测】**

- “进入直播画面”在默认的“影棚”背景下会自动切成**透明**（`broadcast.mjs:9-10`），但窗口捕获抓不到透明，应该切成**绿幕**。
- 引导最后一步点“打开绿幕画面”后，对话框关闭、整窗变绿：没有“按 Esc 返回”的提示（footer 在直播模式下被隐藏），也没有“下一步去 OBS 或直播软件”的指引，而且引导不会被标记为完成，下次启动还会再弹出。
- 主界面“复制 OBS 浏览器源地址”仍然是最显眼的按钮，复制后提示“添加浏览器来源后粘贴即可”，与文档所说的“实验方案”相矛盾；在 Tauri 中复制出来的是 `http://tauri.localhost/...`，OBS 根本访问不到。

### 4.4 测试有效性：看起来覆盖、实际没覆盖

- `tests/runtime-contract.test.mjs`、存储测试：**全部是对源代码做正则匹配**。例如 `/latestHead\.copy\(neutralHead\)/` 在符号写反、代码走不到、调用顺序错误时依然会通过。

### B. 非常通俗易懂地创造出自己的角色

**现状**：
- 制作角色的全部指导只有：`BEGINNER_GUIDE.md` 6 行文字、引导弹窗里 4 行（还折叠在“怎么制作？”里）、离线帮助 1 句话。
- 链接是英文页面 `vroid.com/en/studio`。
- 没有导出设置说明，也没有配图或视频。
- 计划书里写着“v1.0 不自研捏人”（`PROJECT_PLAN.md:38,104`），**与“非常通俗易懂地创造出自己的角色”这一方向存在冲突，需要你做决策**。

**建议分四级推进**（前两级不写代码或只写很少的代码）：

| 级别 | 内容 | 成本 | 建议时间 |
|---|---|---|---|
| L0 示例角色 | 委托或征集 2–3 个**原创、CC0 或 CC BY 授权**的 VRM（如男、女、Q 版各一个），内置在程序中；首次打开直接出现，并提供“先用示例角色试试”按钮 | 美术预算或社区征集；代码约 0.5 天 | 立即启动 |
| L1 一页式“做角色”向导 | 图文加视频，按顺序讲清：安装 VRoid（中文界面，Steam 或官网）→ 选择预设 → 改脸、发型、衣服 → **导出设置**（VRM 1.0、缩减多边形、合并材质、贴图 2048，这些阈值要与模型检查一致）→ 填写作者和使用许可（逐项解释“允许直播 / 商用 / 署名”分别是什么意思）→ 回到喵动导入。另外讲清 VRoid Hub 上“允许下载 + 允许直播”的模型如何识别和使用 | 文档加视频 2–3 天，不写代码 | v0.2.x |
| L2 应用内“轻捏人” | 基于 L0 的示例角色，在喵动里直接修改**发色、瞳色、肤色、服装颜色**（改 MToon 材质颜色），切换**发型和配饰**（显示或隐藏预制网格），起名字，保存为“我的角色”。不导出 VRM，只在喵动内使用 | 中等（1–2 周）；需要美术提供可切换的部件 | v0.3 |
| L3 远期 | 照片或文字生成角色：技术尚不成熟，还有肖像权、未成年人等风险，**不建议 v1.0 做** | 高 | 观察 |

L0 加 L1 就能让小白 10 分钟内得到“一个能动的角色”和“一条做自己角色的清晰路线”；L2 才真正实现“在喵动里创造自己的角色”，它与“不做完整捏人系统”并不矛盾，因为它只在自有角色的基础上做换装、换色，范围可控。

### C. 对接多家平台

**核心判断**：国内平台分为三类，接入方式不同：

| 类型 | 平台 | 最佳接入方式 | 现状 | 缺口 |
|---|---|---|---|---|
| 支持“窗口捕获”的直播工具 | OBS、B站直播姬、抖音直播伴侣、快手直播伴侣、虎牙直播助手、斗鱼直播伴侣 | 窗口捕获 + 绿幕抠图 | ⚠️ 有文字指南，但**直播画面空白（①）导致全部不可用** | 修复①后逐个配截图；虎牙、斗鱼没有指南；需提醒开播资质和实名认证 |
| 只认“摄像头”的软件 | 腾讯会议、钉钉、飞书、Zoom、Teams、微信视频号直播（手机端）、部分直播伴侣的“摄像头”素材 | **虚拟摄像头** | ⚠️ 只有“借助 OBS 虚拟摄像头”的过渡说明 | 原生虚拟摄像头没有开始；过渡说明有误（见下） |
| 推流码直播 | B站、抖音、快手、视频号、小红书、虎牙、斗鱼网页开播 | OBS + 平台推流码（RTMP） | ❌ 没有说明 | 需要一篇“拿推流码 → 填进 OBS”的通用教程 |

**需要修正的技术描述**：
- `LIVE_PLATFORM_GUIDE.md:46` 写“在 OBS 抠出角色后开启虚拟摄像头”。虚拟摄像头**不支持透明通道**，抠掉的区域会变成黑色，应改为“保留绿幕或换成背景图，再在会议或直播软件里抠像”。同一处“第一节”也指错了位置，OBS 在第二节。
- 竖屏平台（抖音、快手、视频号）需要说明 OBS 画布怎么设成 1080×1920；喵动的 9:16 输出目前在直播画面里是错位的（⑤）。
- 窗口遮挡：单屏幕的小白一打开 OBS 就会把喵动窗口挡住。需要给出具体办法：左右并排窗口；或关闭浏览器的遮挡检测；窗口捕获黑屏时改用“Windows 10（1903 及以上）”捕获方式。

**原生虚拟摄像头是扩大平台覆盖面最关键的一项功能**（一次开发，所有会议软件和“摄像头”类来源都能用）：
- Windows 11 可以用系统自带的虚拟摄像头接口（`MFCreateVirtualCamera`，Win11 22H2 及以上）；
- Windows 10 需要 DirectShow 方案，可评估 MIT 协议的开源实现；
- 在 Tauri 中以 Rust 插件接入，输出绿幕或自选背景；
- 建议作为 v0.4“直播可用性”的首要技术验证项。

**进阶互通**（v1.0 之后）：Spout2（OBS 高性能输入）、VMC 协议（与 VSeeFace、Warudo 等工具互通）、NDI（注意许可）。
