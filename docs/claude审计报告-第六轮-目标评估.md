# Claude 审计报告 · 第六轮：目标评估（v0.3.1-beta）

> 评估日期：2026-09-29
> 代码基线：本轮整改后的 v0.3.1-beta（整改明细见 [第五轮整改记录](ROUND5_REMEDIATION.md)）
> 目标：①零基础小白开箱即用；②非常通俗易懂地创造自己的角色；③能对接多家直播和会议平台

---

## 一、结论

**三个目标的主干都已经具备，但都还没有得到真实世界的验证。**

- **代码层面**：一个小白可以下载安装版或便携版，双击打开，一键用原创角色"喵小动"，改名字、换耳朵尾巴发型衣服、换颜色、导出，开摄像头动起来，再按平台向导接入 10 类直播和会议平台。整条路径我在浏览器里走通了：全程中文，不需要命令行，不联网，也没有页面报错。
- **最大的缺口不在代码**：
  1. 所有 Windows、摄像头、直播软件、会议软件、iPhone 相关的功能，**没有一项在真实电脑上跑过**，目前只有自动化测试和 CI 证据；
  2. 没有国内下载渠道，也没有代码签名。国内小白"下载 → 双击"这一步本身就可能卡住；
  3. 角色的美术质量和可选范围，离"创造自己的角色"还有明显距离。

打个比方：房子的结构已经建好，水电也按图纸接通了，但还没有人真正住进去试过，门口的路（下载渠道）也还没修好。

---

## 二、评判标准

沿用第一轮报告定下的可执行标准：找 5–10 名从未接触过虚拟主播的用户，只给一个下载链接、不做任何指导，看是否达到以下两点：

- 10 分钟内看到自己的角色动起来的比例 ≥ 80%；
- 20 分钟内出现在自己常用的直播或会议软件里的比例 ≥ 80%。

这个测试**还没有做过**，所以下面的评估都是"具备条件"层面的，不是"已经达标"。

## 三、逐项评估

### 目标①：小白开箱即用

| 环节 | 状态 | 证据与说明 |
|---|---|---|
| 获取 | ⚠️ | GitHub 上有正式测试版，提供安装版和便携版两种，都附校验值。但**没有国内下载镜像**，国内访问 GitHub 慢或下载失败 |
| 信任 | ❌ | 程序**未签名**，Windows 会弹"已保护你的电脑"；开启"智能应用控制"的 Windows 11 可能直接拦截。发布说明已教用户核对校验值，但没有从根本上解决 |
| 启动 | ✅（未经真机） | 安装版不需要任何前置软件；便携版解压后双击启动。CI 在 Windows 上实际完成了安装、启动、卸载 |
| 第一眼 | ✅ | 首页三个入口，一键加载喵小动；引导可跳过；没有模型或摄像头也能走完引导 |
| 动起来 | ✅（未经真机） | 脸、眼、嘴、头、身体、手都已实现，镜像方向已统一。MediaPipe 左右约定用真人照片实测过，但"真人对着摄像头"的手感从未验证 |
| 接入直播 | ⚠️ | 见目标③ |
| 下次打开 | ✅ | 角色库、配置档、换色和部件都会保存 |
| 出问题时 | ⚠️ | 有离线帮助、诊断报告、平台排查提示；**没有国内反馈渠道**（只有 GitHub Issues） |
| 卸载与升级 | ✅（未经真机） | 本轮修复了卸载死锁、升级丢组件、旧版迁移，并增加 CI 场景；UAC 拒绝、标准用户、多用户仍需真机确认 |

**判断**：程序本身已经接近"开箱即用"。挡住小白的是外部条件：下载渠道、签名、真机验证。

### 目标②：通俗易懂地创造自己的角色

| 能力 | 状态 | 说明 |
|---|---|---|
| 不会做角色也能马上开始 | ✅ | 原创喵小动 + pixiv 官方示例，一键加载 |
| 在程序里改出"自己的"角色 | ⚠️ | 喵小动可以改名字，耳朵、尾巴、发型、衣服**各 2 种**，任意部位换色，恢复原色 |
| 导出并带走 | ✅ | 导出 VRM，格式校验 0 错误，重新导入可用；许可允许直播、商用、修改再分发 |
| 美术质量 | ❌ | 喵小动由简单几何体拼成，没有贴图和描边；换成圆耳朵后更像熊。作为"自己的形象"吸引力不足 |
| 深度定制 | ❌ | 没有脸型、眼睛样式、表情风格、配饰等选项；其他 VRM 角色只能换色 |
| 做更精细的角色 | ⚠️ | 有 VRoid Studio 图文向导（中文入口、导出参数、许可说明），但没有视频，而且需要离开喵动、学另一个软件 |

**判断**：已经从"只能导入别人的模型"进步到"能在程序里改出一个不一样的角色"，但 2 种 × 4 类部件加换色，能组合出的变化有限，美术也还是占位水平。要真正做到"创造自己的角色"，**瓶颈是美术资源，不是代码**。

### 目标③：对接多家平台

| 平台类型 | 接入方式 | 状态 |
|---|---|---|
| OBS | 窗口捕获 + 抠绿幕；一键自动配置 OBS 场景 | ✅ 自动配置经协议模拟测试；真实 OBS 未验证 |
| B站直播姬、抖音、快手、虎牙、斗鱼直播伴侣 | 窗口捕获 + 抠绿幕；或选"MIAO Motion Camera" | ⚠️ 有逐平台步骤，但菜单名未经真机核对 |
| 视频号、小红书 | 电脑端推流或开播工具 | ⚠️ 有步骤；**手机端开播无法使用电脑的虚拟摄像头**（平台限制） |
| 腾讯会议、钉钉、飞书、Zoom、Teams | 原生虚拟摄像头；或 OBS 虚拟摄像头中转 | ⚠️ 原生摄像头仅 64 位、640×360、15 帧、无透明，32 位软件看不到；CI 中 ffmpeg 能收到真实角色画面，但**没有在任何会议软件里试过** |
| 推流码 | OBS 填推流地址和密钥 | ✅ 有通用教程 |
| 手机面捕 | iFacialMocap（iOS） | ⚠️ 只支持付费 iOS App，安卓没有方案；从未在真 iPhone 上试过 |

**判断**：覆盖面已经足够（10 类平台都有路线和步骤），**可用性没有证据**。最关键的原生虚拟摄像头还有 64 位、低分辨率、固定横屏三个限制。

## 四、缺口清单

按"谁能补"分类：

### A. 需要真机（最优先，没有替代办法）

1. Windows 10、Windows 11 各一台，其中一台用**标准用户**账户：安装、启动、卸载，从 v0.3.0-beta 升级，在 UAC 弹窗里点"否"。
2. 镜像方向：同时闭左眼、举左手、向左转头，看角色三处是否在同一侧（只需改一个常量即可整体翻转）。
3. 虚拟摄像头在腾讯会议、钉钉、飞书、直播伴侣里能否看到、能否用，并记录这些软件是 32 位还是 64 位。
4. OBS 自动配置、窗口捕获、绿幕抠图的实际效果。
5. iPhone + iFacialMocap：连接、转头方向、防火墙提示。
6. 360、火绒对安装和组件注册的反应。
7. 低配电脑（集成显卡）上的帧率，连续使用 1 小时是否稳定。
8. **3–5 名零基础用户试用**（第二节的标准）。

### B. 需要外部资源或账号

1. **国内下载镜像**（Gitee Release、对象存储或网盘）。发布流程里已预留上传步骤，只差账号和密钥。
2. **代码签名**（SignPath 开源免费签名，或购买证书；也可以评估上架 Microsoft Store）。
3. **美术**：正式版喵小动（贴图、描边、更好的比例），以及每类 4–6 种部件，最好再加一两个不同风格的原创角色。
4. **视频教程**（B站）：从下载到开播的完整录屏。
5. **国内社区渠道**：QQ 群或 B站账号，用于收集反馈。
6. 编辑旧版 v0.3.0-beta 的 Release 正文，加安全警告（文案见 [第五轮整改记录](ROUND5_REMEDIATION.md)）。

### C. 代码还可以继续做

| 优先级 | 事项 | 价值 |
|---|---|---|
| 高 | 虚拟摄像头：增加 720p 和竖屏 9:16 格式；编译 32 位组件 | 直接扩大会议和直播软件的兼容面 |
| 高 | 捏人扩展：预设配色、"随机一个"按钮，并为美术资源预留部件接口 | 美术到位后，能立刻扩成更多组合 |
| 中 | 首次运行"一分钟体检"：自动检测摄像头、显卡、网络类型（公用/专用），并给出建议 | 在用户看到错误之前就提前指出问题 |
| 中 | 签名到位后接入自动更新（更新源放在国内镜像） | 减少用户停留在有问题的旧版本 |
| 中 | 安卓面捕：评估声称兼容 iFacialMocap 协议的安卓 App（需真机） | 覆盖安卓用户 |
| 低 | 文档瘦身：把历次审计、整改记录移到 `docs/archive/`，面向用户的只保留"新手教程、平台指南、下载、帮助"几份 | 现在 `docs/` 下近 20 个文件，新人和贡献者容易迷路 |
| 低 | 主程序包 850 KB，首屏加载可以再拆分 | 低配电脑首屏更快 |

## 五、建议的下一步

1. **本周**：确认 v0.3.1-beta 发布，并编辑旧版 Release 加警告（B-6）。
2. **一周内**：做一次真机验收冲刺（A-1 到 A-7），优先确认镜像方向和虚拟摄像头。发现的问题由 Codex 修复。
3. **两周内**：搭好国内镜像和签名（B-1、B-2）。这两项解决之前，不建议大范围推广。
4. **同步进行**：请美术做正式版喵小动和部件（B-3），代码侧先做 C 中的"捏人扩展"和"虚拟摄像头格式"。
5. **以上完成后**：做零基础用户试用（A-8），用第二节的两个 80% 指标判断三个目标是否真正达成。
