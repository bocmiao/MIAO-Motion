# 项目现状审计

> 审计日期：2026-09-28  
> 审计基线：v0.2.1 候选版  
> 原则：代码存在不等于真机通过；规划存在不等于功能完成。

## 1. 已完成

### 产品和开源基础

- 产品定位、目标用户、竞品、版本路线、风险和验收门槛已经成文。
- 采用 MPL-2.0；第三方依赖、模型资产和商标边界已说明。
- README、贡献指南、安全策略、更新日志、Issue 表单、PR 模板和 Dependabot 已建立。

### 当前可运行功能

- VRM 0.x/1.0 文件选择与拖放导入。
- Three.js + three-vrm 角色渲染、相机旋转和自动取景。
- MediaPipe Face Landmarker 驱动头部、左右眨眼、眼神、张嘴和微笑。
- 正面校准、帧率无关平滑、动作幅度调整和人脸丢失回正。
- 摄像头枚举、选择、切换、释放和常见错误中文提示。
- 基础模型检查：头部、眨眼、嘴型、视线，并解释缺失影响。
- 影棚、绿幕、透明背景；普通预览和无界面直播画面。
- OBS 浏览器来源地址复制及绿幕窗口捕获后备路径。
- 最近一个模型存入 IndexedDB；摄像头、背景、幅度和引导状态本地保存。
- MediaPipe JavaScript 按需加载；WASM 和模型在构建时校验并进入本地运行包。

### 小白体验

- 首次启动自动出现四步引导。
- 无模型用户可从应用内进入 VRoid Studio 制作路径。
- 每一步显示是否具备继续条件，不能在未导入模型、未开摄像头时误跳过关键步骤。
- 新手教程可随时重开；关闭不代表完成，完成后才停止自动弹出。
- 零基础文档覆盖安装、制作模型、摄像头、校准、OBS、常见错误和隐私。

### 自动验证

- 动作求解、设置、文件边界、摄像头错误、引导状态、离线资源和 DOM 契约测试。
- TypeScript 类型检查、Vite 生产构建、依赖高危漏洞审计和 GitHub Actions。

## 2. 部分完成

| 能力 | 已有 | 缺口 |
|---|---|---|
| 模型医生 | 4 项核心能力和缺失影响 | 还没有骨骼全量、纹理尺寸、面数、材质和内存估算 |
| 模型存储 | 自动恢复最近一个模型 | 还不是可重命名、缩略图、删除的模型库 |
| OBS | 浏览器地址和绿幕后备教程 | 未真机验证；没有自动创建来源、Spout2 或原生透明窗口 |
| 离线运行 | 构建产物含 WASM/模型 | 当前首次源码构建仍需联网；尚无桌面安装包验证 |
| 错误处理 | 常见文件和摄像头错误可解释 | WebGL 初始化、极端显存不足和部分损坏 glTF 仍缺细分提示 |
| 无障碍 | 中文语义、键盘按钮、状态播报、原生 dialog | 尚未经过读屏软件和完整键盘路径人工审计 |
| 性能 | MediaPipe 延迟加载，脸部模式可限频 | 没有真实硬件 FPS、延迟、内存和长时间数据 |

## 4. 现在还能做得更好的地方

按收益和风险排序：

1. **先完成真实硬件 Gate A**：验证头部轴、左右眼、摄像头释放和最低 15 FPS。这决定 solver 是否正确，是进入桌面封装前最重要的证据。
2. **建立合法测试模型集**：至少 5 个 VRM，覆盖 0.x/1.0、分离/合并眨眼、有无 LookAt；不能把无授权模型提交仓库。
3. **做 Tauri 最小桌面包**：Gate A 通过后只封装现有功能，先实现离线安装、文件目录和干净机启动，不同时加入身体追踪。
4. **升级模型医生**：优先增加阻断/提醒分级、纹理尺寸和基础内存估算，减少“模型为什么卡”的重复问题。
5. **增加浏览器端到端冒烟**：在需要验证 dialog、导入按钮和设置恢复的交互回归时，再引入最小 Playwright 测试；当前 DOM 契约测试已覆盖结构，但不能代替真实点击。
6. **拆分 `main.ts`**：当桌面壳或身体追踪开始进入主线时，再按 Capture/Tracking/Avatar/Broadcast 拆分。当前提前拆只会增加文件跳转。

## 5. 当前最佳下一步

在没有真机期间，代码可以继续做模型医生和桌面封装准备，但不应开始身体/手部或宣称 v0.2.1 发布。取得一台 Windows 设备或招募一名志愿测试者后，按 [`ACCEPTANCE.md`](ACCEPTANCE.md) 第 1 节执行，失败项优先于新功能。
