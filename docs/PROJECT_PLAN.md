# MIAO Motion / 喵动：完整项目计划书

> 文档版本：1.0  
> 基线日期：2026-09-28（Asia/Shanghai）  
> 对应代码：v0.2.1 候选版（自动化检查完成，真机验收待执行）
>
> 项目性质：免费、开源、本地优先；源代码使用 MPL-2.0

## 1. 一页结论

MIAO Motion 是面向零基础用户的 Windows 端 3D 虚拟形象动捕工具。用户只需普通摄像头和一个 VRM 模型，即可完成角色导入、模型检查、动作校准和 OBS 直播。

项目不以“功能最多”为第一目标，而以以下四件事作为差异化：

1. **第一次使用成功率高**：三步完成导入、开摄像头、开播。
2. **错误可解释**：模型缺骨骼、缺表情或性能过重时，用中文告诉用户问题和解决办法。
3. **隐私边界清楚**：默认不注册、不上传摄像头、不上传模型、不启用遥测。
4. **完全免费且可审计**：核心代码公开，Windows 安装包免费，不设置导出水印或付费解锁。

v1.0 的产品定义不是“全能 VTuber 工作室”，而是：

> 一个普通人能在十分钟内学会、用普通摄像头稳定驱动 VRM，并顺利放进 OBS 的免费工具。

## 2. 已确定的原则

| 项目 | 决定 | 理由 |
|---|---|---|
| 代码协议 | MPL-2.0 | 修改过的 MPL 文件需继续公开，同时允许与独立闭源模块组合，适合长期生态扩展 |
| 官方发行 | 免费，不收费 | 不做订阅、导出水印、功能付费墙或模型抽成；MPL-2.0 仍允许第三方商业使用代码 |
| 数据处理 | 本地优先 | 摄像头帧、模型和校准数据默认只留在设备上 |
| 首发平台 | Windows 11 64 位；Windows 10 22H2 尽力兼容 | OBS/VTuber 用户集中，Spout2 也以 Windows 为主；Windows 10 已结束常规支持 |
| 首发模型 | VRM 0.x、VRM 1.0 | 生态成熟，VRoid Studio 可直接导出 |
| 首发追踪 | 普通 RGB 摄像头 | 不要求 iPhone、Leap Motion、VR 设备或穿戴传感器 |
| 首发直播 | 透明窗口/绿幕；评估 Spout2 | 先保证稳定，再增加零拷贝纹理输出 |
| 账号与云端 | v1.0 不做 | 对核心体验无帮助，会增加隐私、成本和运维负担 |
| 角色编辑器 | v1.0 不自研 | 引导用户使用 VRoid Studio；完整捏人系统是另一个产品 |
| Live2D | v1.0 不支持 | 与 VRM 的渲染、骨骼、SDK 和授权体系完全不同 |

### 2.1 MPL-2.0 与 GPL-3.0 取舍

这里比较的是本项目可能采用的 **MPL-2.0** 与 **GPL-3.0-or-later**，不是 LGPL、AGPL，也不是“仅 GPL-2.0”。两者都允许免费或收费使用、复制、修改和分发；“开源”不等于“禁止商业使用”。差异主要在分发组合程序时，需要开放到什么范围。

| 维度 | MPL-2.0 | GPL-3.0-or-later | 对 MIAO Motion 的影响 |
|---|---|---|---|
| Copyleft 范围 | 文件级：被修改的 MPL 文件继续按 MPL 提供源码 | 程序级：形成一个组合/派生程序并分发时，整体通常需按 GPL 兼容条款提供对应源码 | MPL 更适合未来保留独立插件、SDK 或商业品牌模块的选择空间 |
| 与闭源代码组合 | 可与独立闭源文件组成 Larger Work；MPL 文件本身的源码义务不消失 | 紧密链接或构成一个程序的闭源模块通常不能随 GPL 程序作为闭源组合分发 | GPL 更能阻止下游把核心扩展成闭源整包，MPL 更利于集成 |
| 修改回馈强度 | 中等；重点保证现有文件的修改回流 | 强；重点保证分发的完整派生程序保持自由 | GPL 的社区回馈保障更强，MPL 的采用阻力更低 |
| 插件边界 | 独立新文件可使用其他许可证，边界相对清楚 | 是否必须 GPL 取决于通信、链接和是否构成单一组合程序，容易产生边界讨论 | 若以后有插件 API，MPL 对普通开发者更容易解释 |
| 私下修改 | 不分发时通常不触发源码提供义务 | 不分发时通常也不触发源码提供义务 | 两者都不是“改了就必须立刻公开”；SaaS 强制公开需考虑 AGPL，而非 GPL |
| 商业使用 | 允许 | 允许 | 不能靠任一许可证禁止倒卖；应靠免费官方发行、商标和可信构建保护用户 |
| 许可证兼容 | 可吸收 MIT/BSD/Apache-2.0 等许可代码并保留必要声明；默认条款提供向部分 GNU 次级许可证组合的路径 | 能组合的依赖必须 GPL 兼容；GPLv3 比 GPLv2 兼容范围更宽 | 当前 MediaPipe/three-vrm/Tauri 依赖路线用 MPL 更直接 |
| 贡献者接受度 | 企业和个人通常更容易接受，但下游新文件可闭源 | 强开源立场清晰，但可能减少有闭源集成需求的贡献者 | 本项目以普及、易复用和免费官方版为优先，MPL 更匹配 |
| 更适合的目标 | 开放核心，同时容许更大作品含独立不同许可模块 | 要求下游分发的完整衍生程序也保持开源 | 如果未来目标改成“任何衍生桌面版必须整体开源”，再讨论 GPL |

最终决定：继续使用 **MPL-2.0**，不在许可证外增加“禁止商用”等冲突条款，也不把 `Incompatible With Secondary Licenses` 通知加入源码。配套措施是：

1. 对被修改的 MPL 文件严格履行源码与许可通知义务。
2. 新增第三方代码时记录来源、版本、许可证和修改情况。
3. 以独立的商标政策保护“MIAO Motion / 喵动”名称与 Logo，避免非官方构建冒充官方版。
4. 示例角色、字体和宣传素材分别授权，不假设它们自动适用 MPL。
5. 若未来更换到 GPL，先完成版权归属、贡献者同意和依赖兼容审计；不能只替换一份 `LICENSE` 文件。

以上是项目工程决策，不替代针对具体分发方式的法律意见。

## 3. 用户与核心场景

### 3.1 第一目标用户

- 第一次尝试虚拟主播，不懂骨骼、BlendShape、Spout 或 OBS 参数的人。
- 已有 VRoid/VRM 模型，希望用普通摄像头开播的人。
- 希望在会议、录课、视频或直播中隐藏真人面部的人。
- 想研究或二次开发本地动捕能力的中文开发者。

### 3.2 暂不优先的用户

- 需要电影级光学动捕、多人同步或专业棚拍的团队。
- 只使用 Live2D Cubism 模型的主播。
- 必须依赖 iPhone TrueDepth/ARKit 舌头、脸颊等高精度系数的专业用户。
- 需要完整 3D 场景编辑、复杂节点图和商业插件市场的工作室。

### 3.3 三条核心用户旅程

#### A. 已有 VRM，第一次开播

1. 安装并打开程序。
2. 拖入 VRM。
3. 程序自动检查骨骼、表情、纹理和性能。
4. 选择摄像头，完成正面校准。
5. 预览头部、眼睛和嘴型。
6. 点击“添加到 OBS”或按新手教程添加捕获源。
7. 进行 60 秒开播前检查。

目标：首次成功开播中位时间不超过 10 分钟。

#### B. 没有模型

1. 首页选择“我还没有角色”。
2. 用图文说明跳转 VRoid Studio 官方下载/制作流程。
3. 按固定导出预设生成 VRM 1.0。
4. 回到 MIAO Motion 导入并检查。

v1.0 不在程序内复制一个低质量捏人系统。

#### C. 已会使用 OBS

1. 导入并校准角色。
2. 选择透明输出或 Spout2。
3. 自动/手动创建 OBS 来源。
4. 保存为本地配置档，下次直接恢复。

## 4. 市场与竞品结论

### 4.1 直接和邻近竞品

| 产品 | 类型 | 主要优势 | 对新手的主要门槛 | MIAO Motion 借鉴点 |
|---|---|---|---|---|
| VTube Studio | Live2D，免费增值 | 跟踪成熟、参数映射自由、热键和道具生态完整 | 主要服务 Live2D，不解决 VRM；高级效果配置较多 | 首次引导、参数反馈、热键和道具交互 |
| VSeeFace | 免费 VRM Windows 软件 | VRM、脸/手追踪、画质和 Spout2 输出成熟 | 界面和参数偏技术化，Windows 限定，非完整开源产品 | Spout2、质量优先、模型兼容提示 |
| Warudo | 3D VTuber 工作室 | 场景、道具、Blueprint、C# 插件和多种输出能力强 | 功能密度大，学习成本高 | 高级模式与基础模式分离；输出方案 |

| XR Animator | 摄像头全身动捕 | 单摄像头支持脸、身体、手，功能覆盖广 | 设置复杂；源代码许可带非商业与相同方式共享限制 | 只学习交互和算法思路，不复制代码 |
| VRoid Studio | 角色制作工具 | 零基础创建角色，可导出 VRM 0.x/1.0 | 不是直播动捕软件 | 作为官方推荐的模型创建入口 |

### 4.2 可占据的位置

成熟竞品大多在两个方向形成优势：

- 专业能力强，但设置和概念较多；
- 入门简单，但局限于 Live2D、键鼠姿态或特定硬件。

MIAO Motion 应坚持以下位置：

> 比专业工作室简单，比纯展示工具完整；不追求节点图和插件数量，优先把模型诊断、校准和 OBS 连接做成中文向导。

“官方版本永久免费”和“MPL-2.0 允许商业使用”必须同时成立。项目不能用附加条款禁止他人商业使用 MPL 代码，但可以保护 MIAO Motion 名称、Logo 和单独授权的角色资产。

### 4.3 不应复制的竞品路线

- 不在 v1.0 构建 Warudo/VNyan 式节点编辑器。
- 不做模型商城、云端账号和直播平台社区。
- 不承诺一个摄像头达到专业惯性/光学动捕精度。
- 不复制 XR Animator 代码：其核心使用 CC BY-NC-SA 4.0，和本项目免费但允许广泛使用的 MPL 目标不一致。
- 不新增 Kalidokit：其项目已明确标记为弃用，当前 MediaPipe Tasks 已直接提供 BlendShape 和姿态结果。

## 6. 产品功能全景

### 6.1 P0：v1.0 必须具备

#### 安装与首次使用

- Windows x64 安装包和免安装压缩包。
- 首次启动检查 WebView2、摄像头、GPU/WebGL 和磁盘空间。
- 中文三步向导；每一步都有“为什么”和“出错怎么办”。
- 无模型用户获得 VRoid Studio 官方引导。
- 示例角色只有在许可证允许再分发时才随包提供，否则不捆绑。

#### 模型系统

- 导入 VRM 0.x/1.0。
- 本地模型库：名称、缩略图、最近使用、删除和重新导入。
- 模型医生：骨骼、表情、LookAt、材质、贴图尺寸、面数和内存估算。
- 明确区分“阻断问题”“可以继续的警告”“优化建议”。
- 模型许可提醒：程序能读取 VRM 元数据，但不替用户保证直播/商业权利。

#### 动捕

- 头部转向、俯仰、侧倾。
- 左右眼眨眼、眼神方向、基础嘴型和微笑。
- 上半身：肩、胸、脊柱、上臂、前臂。
- 双手开合和主要手指弯曲；性能不足时允许关闭。
- 正面校准、身体校准和一键重新居中。
- 动作平滑、灵敏度、幅度和左右镜像设置。
- 人脸丢失时平滑回到休息姿势，不突然抽动。

#### 直播输出

- 透明窗口和绿幕输出。
- Windows 上验证 Spout2；通过质量门槛后作为推荐输出。
- OBS 新手向导，检查画布尺寸、透明度和来源是否存在。
- 可选 obs-websocket 5.x 集成；密码只保存在系统安全存储，不写日志。
- 直播配置档：模型、机位、背景、灵敏度、输出分辨率。

#### 稳定性与隐私

- 默认完全离线运行；模型与 MediaPipe 资源随桌面安装包分发。
- 无账号、无广告、无默认遥测。
- 摄像头指示状态始终可见，停止后立即释放设备。
- 异常退出后恢复上一次有效设置，但不自动恢复摄像头权限。
- 日志不包含帧、音频、模型内容、OBS 密码或本机敏感路径。

### 6.2 P1：v1.0 后优先

- 麦克风音量驱动口型，摄像头嘴型失败时自动降级。
- 键盘、鼠标、手柄的桌面/游戏姿态。
- 表情热键、随机待机动作和可导入动画。
- VMC 协议输入/输出，与其他追踪器或渲染器组合。
- iPhone/ARKit 数据接入。
- macOS 版本与 Syphon 输出可行性。
- 多语言界面。

### 6.3 P2：有社区需求再做

- 轻量角色换装或预设编辑；不复制完整 VRoid 功能。
- 道具和简单跟随挂点。
- 插件 API 与独立插件仓库。
- 多角色同屏、多人追踪。
- Linux 包和 PipeWire/共享纹理输出。

### 6.4 明确不做

- 云端人脸识别或身份识别。
- 人脸替换、真人 Deepfake 或绕过肖像权限制的功能。
- 未经授权的模型抓取、解密或格式破解。
- 直播平台刷量、自动互动或规避平台规则。
- v1.0 内的账号、好友、市场、支付、广告和 NFT。

## 7. 信息架构与新手界面

### 7.1 首页只保留三个主动作

1. 选择角色。
2. 开启摄像头。
3. 开始直播。

性能、骨骼和网络术语默认折叠到“高级设置”。首页不出现 BlendShape、Quaternion、WebSocket 端口等内部概念。

### 7.2 状态语言规范

每个错误必须包含三段信息：

- 发生了什么：例如“没有检测到嘴型表情”。
- 是否可以继续：例如“头部和眨眼仍可使用”。
- 怎么解决：例如“在 VRoid Studio 导出时启用基础表情”。

禁止只显示错误码、异常堆栈或“未知错误”。

### 7.3 模型医生等级

| 等级 | 含义 | 行为 |
|---|---|---|
| 通过 | 功能完整且性能合理 | 直接进入校准 |
| 提醒 | 缺少非核心能力 | 允许继续，并说明影响 |
| 阻断 | 文件损坏、非 VRM、核心骨骼缺失 | 不进入动捕，提供修复路径 |
| 性能风险 | 纹理、材质或网格过重 | 允许继续，提供估算和降级建议 |

## 8. 技术架构

### 8.1 当前 v0.2.1

```text
VRM 文件 → IndexedDB → three-vrm → Three.js → 浏览器画布
摄像头 → MediaPipe Face Landmarker → 校准/平滑 → 头部与表情
```

优点：验证速度快、无后端、核心链路已跑通。  
限制：源码首次安装/构建需要网络；推理在主线程；OBS 浏览器来源的摄像头权限因环境而异；没有原生安装包。

### 8.2 v1.0 目标

```text
┌──────────────────── Windows 桌面应用（Tauri） ────────────────────┐
│ UI/向导  模型库  设置  诊断  日志                                  │
│                                                                  │
│ Camera → MediaPipe Worker → Motion Solver → VRM Retargeting      │
│                              ↓                                   │
│                        Three.js Renderer                         │
│                              ↓                                   │
│          Preview / Transparent Window / Spout2 Feasibility       │
└──────────────────────────────┬───────────────────────────────────┘
                               │ optional localhost + auth
                         OBS WebSocket 5.x
```

### 8.3 模块边界

| 模块 | 职责 | 不应承担 |
|---|---|---|
| Capture | 摄像头枚举、权限、帧率、释放 | VRM 逻辑 |
| Tracking | Face/Pose/Hand 推理和质量分数 | UI 文案、OBS 控制 |
| Solver | 坐标转换、校准、滤波、约束 | 模型加载 |
| Avatar | VRM 加载、诊断、骨骼与表情映射 | 摄像头权限 |
| Renderer | 场景、灯光、背景、分辨率和输出 | 账号或网络请求 |
| Broadcast | 透明窗口、Spout2、OBS 连接 | 动作求解 |
| Storage | 模型索引、配置、迁移和清理 | 原始摄像头帧 |

### 8.4 数据存储

v0.2.1 使用 IndexedDB 保存当前模型、LocalStorage 保存摄像头/背景/灵敏度/画质设置；设置档可手动导入导出，诊断报告按需下载且不包含模型内容、画面、本机路径或设备编号。桌面版使用本地 JSON 清单加文件目录：

```text
MIAO Motion/
  config.json
  profiles/
  avatars/
  cache/
  logs/
```

直到出现需要事务、复杂查询或大量索引的真实需求，才评估 SQLite。

### 8.5 动捕策略

- 脸、身体、手分别可开关，低性能设备优先保脸。
- 推理与渲染解耦：推理可为 15–30 FPS，渲染保持 30–60 FPS。
- 使用时间相关阻尼，避免不同帧率下手感变化。
- 所有关节设置合理角度上限，异常帧不能把骨骼扭坏。
- 根据追踪置信度动态增加平滑，而不是固定一个滤波强度。
- 身体和手在加入主线前必须先通过 Worker 原型和性能基准。

## 11. 测试与验收策略

## 12. 隐私、安全与合规

### 12.1 隐私承诺

- 不创建用户画像，不做人脸身份识别。
- 不保存原始摄像头帧，不默认保存录制视频。
- 任何未来遥测必须默认关闭、列出字段并单独征得同意。
- 错误报告默认在本地生成，用户查看内容后主动上传。

### 12.2 本地攻击面

- 本地服务只监听 `127.0.0.1`。
- OBS WebSocket 保持认证，凭据进入系统安全存储。
- 所有文件输入视为不可信：限制大小、捕获解析异常、不执行模型内脚本。
- Tauri 权限使用最小 allowlist，不暴露任意 Shell 执行。
- 自动更新必须签名；更新失败保留可启动的上一版本。

### 12.3 模型与人物权利

- 用户必须拥有模型使用和直播权。
- 示例角色必须保存来源、作者、许可文本和再分发证明。
- 不将代码协议错误地宣称适用于用户模型。
- 不把测试用户的脸、动作数据或模型提交到 issue、日志和 CI artifact。

## 13. 开源治理与发布

### 13.1 分支与提交

- `main` 始终可构建。
- 功能通过短分支和 PR 合并；紧急修复仍需 CI。
- 提交使用 `feat:`、`fix:`、`docs:`、`test:`、`refactor:`、`build:`、`ci:`。
- 破坏配置兼容的修改必须提供迁移和回滚说明。

### 13.2 Issue 模板

需要建立四类模板：

- Bug：版本、系统、GPU、摄像头、模型特征、复现步骤；明确禁止上传无授权模型。
- 模型兼容：VRM 版本、缺失项目、VRoid 导出版本、模型许可状态。
- 功能建议：用户问题、当前替代方案、最小验收结果。
- 安全问题：只提供私下报告入口，不在公开 issue 放利用细节。

### 13.3 发布门槛

每个正式版本必须：

1. CI 全绿，依赖锁定。
2. 完成 `ACCEPTANCE.md` 对应版本的 P0 项。
3. 更新 README、第三方许可和版本变更说明。
4. 安装包和便携包均在干净系统验证。
5. 生成 SHA-256；有签名证书后同时完成代码签名。
6. 有明确的已知问题和回滚方式。

## 17. 决策关卡

以下事项必须在进入下一阶段前作出基于数据的决定：

### Gate A：v0.2.1 → v0.3

- 真实摄像头方向、表情和模型兼容是否正确？
- 浏览器原型是否达到最低 15 FPS？
- 如未达到，先修 solver/性能，不做桌面壳。

### Gate B：v0.3 → v0.4

- 安装包是否能在无 Node.js 的干净 Windows 上离线运行？
- 模型与设置升级是否不会丢失？
- 如不稳定，不接入 Pose/Hand。

### Gate C：v0.4 → v0.5

- 身体追踪是否在最低机保持脸部 ≥15 FPS？
- 遮挡恢复是否不出现危险骨骼跳变？
- 如不满足，身体标记为实验功能，不进入默认流程。

### Gate D：v0.5 → v1.0

- Spout2 是否比透明窗口显著更稳定、更省资源？
- 如果收益不明确，则不把原生 Spout2 设为 v1.0 阻断项。
- OBS 自动配置失败时，手动教程必须始终可完成。
