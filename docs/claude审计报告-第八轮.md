## 三、问题与整改建议

### P0-1 main 的 CI 是红的（安装版摄像头测试时好时坏）

- **经过**
  - #68 有两处失败：
    - `windows-portable` 失败，是我上一轮写的发布附件测试在 Windows 上路径解析出错（`URL.pathname` 在 Windows 上得到 `/D:/...`，找不到脚本）。这是我的问题，PR #9 已经顺手修好（改用 `fileURLToPath`）。
    - `windows-desktop` 失败，是安装版测试里一次页面查询卡了 60 秒超时（`#avatar-color`）。
  - 现在 #94 同样是 `windows-desktop` 失败：测试收到红色画面后准备换蓝色，读取已发送帧数的一次页面查询卡了 60 秒（`scripts/check-desktop-camera.mjs:39`）。
- **判断**
  - PR #9 最终提交 `a17677c` 和合并后的 main 代码**完全相同**；在 PR 上 CI 全绿（运行 36623601315），合并后却失败，说明是时好时坏，不是新代码写错。
  - 但它不算偶发：最近 main 上已有 #68、#94 两次卡在同一类地方。根因和之前 CI #66 相同：虚拟摄像头输出和 3D 渲染把页面主线程占满，测试工具的查询排不上队。
- **建议**
  - 不要靠重跑碰运气。
  - 虚拟摄像头输出改成直接在 GPU 上渲染一张 640×360 的小画面再读回，不再每帧把整个大画布缩放复制一遍；或者把像素转换放到后台线程，减轻主线程负担。
  - 测试侧把单次查询的等待和整体超时分开，失败时输出主线程占用情况，便于定位。

### P1-1 创建角色时“保存并返回”不会存进角色库（已实测复现）

- **复现步骤**：点“创建我的角色”→ 起名“布丁猫”→ 点右上角“保存并返回”。
  - 画面上显示“布丁猫”，但角色库里没有；
  - 重启程序后，画面是空的（“角色预览”），角色库也是空的；
  - 重新打开创建器，草稿还在。
- **原因**：`src/character-creator.ts` 里“保存并返回”只保存草稿；只有底栏的“保存到角色库”才会写入角色库。预览时角色以“不保存”方式载入（`loadVrm(file, false)`）。
- **影响**：新手看到“保存”两个字就以为存好了，重启后发现角色不见了，这是最伤信任的体验。
- **建议**：关闭创建器时自动保存到角色库（已存过就更新同一条），按钮改叫“完成并使用这个角色”；只想放弃时用单独的“不保存，返回”。

### P1-2 虚拟摄像头的帧率显示虚高

- CI 日志显示：状态栏写着“12 帧/秒”，但已发送帧数 68 秒只涨了 84 帧，**实际约 1.2 帧/秒**。
- **原因**：`src/native-camera.ts` 的调速只统计了抓取画面的耗时，没有算上把画面交给摄像头组件的等待时间；而这段等待期间不会发下一帧。
- **建议**：按实际发出的帧间隔来显示帧率，调速也要把等待时间算进去。用户遇到会议里画面卡顿时，状态栏得说实话。

### P1-3 从引导里进入创建器后，引导就不回来了

- 在引导第 2 步点“自己创建角色”，引导会被关掉（`character-creator.ts` 的 `open()`）；创建完返回后，引导不会继续到“开摄像头 → 校准 → 开直播”。
- 新手做完角色后不知道下一步做什么，要等下次启动才会重新弹出引导。
- **建议**：记住“是从引导进来的”，关闭创建器后回到引导第 3 步，并显示“✓ 已载入 布丁猫”。
